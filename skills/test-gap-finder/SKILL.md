# test-gap-finder

변경된 소스 파일마다 대응하는 테스트 파일이 있는지 기계적으로 확인한다. 없으면
검토 후보로 보고한다. 테스트 작성이 요청되면 Claude가 코드를 작성한다. 새 분기나
엣지케이스의 실제 커버 여부는 diff와 기존 테스트를 읽고 Claude가 판단한다.

## 실행

```bash
bash ~/.claude/skills/test-gap-finder/scripts/find-gaps.sh          # staged 변경 기준 (기본)
bash ~/.claude/skills/test-gap-finder/scripts/find-gaps.sh last     # 마지막 커밋 기준
```

테스트 파일 자체(경로에 `test_`, `_test`, `.test.`, `.spec.`, `tests/`, `__tests__/`가 있는
파일)는 검사 대상에서 제외한다.

### 파일 검사 후 jev-eval로 후보 검토

변경 종류·소스 확장자·테스트 경로를 먼저 검사한다. `test_<이름>`, `<이름>_test`,
`<이름>.test`, `<이름>.spec`, `<이름>_spec` 파일이 추적 중이면 경로를 보여준다.
없을 때만 diff를 jev로 평가한다. 0~1 값은 실제 확률 측정이 아닌 **모델 추정치**다:

| 출력 | 의미 |
|---|---|
| `후보에서 제외된 이유: 모델 추정치 ...` | 낮은 추정치·충분한 확신도. 제외 이유를 보고하며 테스트 불필요를 확정하지 않는다 |
| `확인 필요, 후보 유지` | 경계·저확신·확신도 누락·입력 잘림. 사람 확인으로 넘긴다 |
| `jev 판정 실패 — 후보 유지` | 호출 실패·응답 오류. 파일 검사 결과를 그대로 보고한다 |

환경변수 `TEST_GAP_NEEDS_TEST_MIN=0.5`, `TEST_GAP_BOUNDARY_MARGIN=0.1`,
`TEST_GAP_LOW_CONFIDENCE=0.5`는 조정 가능한 초기 경험값이다. 추정치가 최소값−경계 폭보다
작고 확신도가 최소 확신도+경계 폭보다 커야 제외한다. `TEST_GAP_USE_JEV=0`이면 모델 호출을
생략한다. diff는 앞 20,000자까지 보내며, 잘렸으면 제외하지 않는다.

## 판단/작성은 Claude가 한다

1. **jev 판정 실패·경계·저확신인 경우** — diff를 직접 읽고 근거를 정리해 사람에게 넘긴다.
   제외된 후보도 이유를 확인해 필요하면 복구한다.
2. **테스트 파일이 없는 경우** — 해당 소스 파일을 읽고, 같은 프로젝트의 기존 테스트
   파일(다른 모듈 것이라도)을 하나 참고해서 테스트 프레임워크/스타일을 파악한 뒤,
   같은 컨벤션으로 새 테스트 파일을 작성한다. 정상 케이스 + 이번 diff가 추가한 분기/
   엣지케이스를 커버한다.
3. **테스트 파일은 있지만 이번 변경을 안 건드린 경우** — `find-gaps.sh`는 이 케이스를
   잡지 않는다(오탐이 많아서 제외함). Claude가 diff와 기존 테스트를 직접 비교해서,
   새로 생긴 분기가 비어 보이면 테스트 케이스를 추가한다.
4. **작성한 테스트는 실제로 돌려서 통과를 확인한다.** 통과 확인 없이 "테스트를
   추가했다"고 보고하지 않는다.

## change-impact와의 연계

`change-impact`가 diff에 소스 파일 변경이 있으면 `find-gaps.sh`를 대신 호출한다. 갭이
있으면 사용자에게 보여주고 테스트를 작성할지 확인받는다. 테스트 없이 진행하는 걸 막지는
않는다 — 판단은 사용자에게 맡긴다.

## 하지 않는 것

- **커밋을 막지 않는다.** 정보 제공 + 제안까지만 자동이고, 테스트 작성 여부와 커밋
  진행은 항상 사용자 확인을 거친다.
- **테스트 커버리지 퍼센트 계산 안 함.** "파일 단위로 테스트가 존재하는가"만 본다.
- **기존 테스트가 부실한지는 판단하지 않는다.** 테스트 파일이 존재하기만 하면
  "파일 없음" 갭에서는 제외된다.
