# 규칙 파일 정리

## 1. 대상 파악

- **`.claude/rules/`가 있으면**: 임계값을 넘은 개별 파일이 정리 대상이다. `rules/`는
  원래 주제별로 나눠 쓰라고 있는 공식 디렉터리라(세션 시작 시 CLAUDE.md처럼 자동
  로드됨), 목표는 "그 파일을 더 작은 주제로 다시 쪼개는 것"이다.
- **단일 `CLAUDE.md`(루트 또는 `.claude/CLAUDE.md`)만 있으면**: 정리 방향을 두 가지 중
  고른다 — (a) **`.claude/rules/`로 주제별 분리**(공식 권장 방식, `.claude/rules/topic.md`
  여러 개로 나눔), 또는 (b) 기존처럼 핵심만 남기고 배경 설명을 `docs/`로 옮김. 프로젝트에
  이미 `docs/`에 여러 세부 문서가 있다면 (b)가, 규칙 자체가 여러 독립 주제로 나뉜다면
  (a)가 자연스럽다 — 애매하면 사람에게 물어본다.
- **`.claude/RULES.md`(비표준 이름)를 발견하면**: 이건 Claude Code가 자동 로드하지
  않는 이름이라는 것부터 사람에게 알린다. 정리하면서 `.claude/rules/`로 옮기면 자동
  로드 문제도 같이 해결된다 — 그냥 파일명만 `CLAUDE.md`로 바꾸는 것도 대안이지만,
  내용이 길어서 정리하러 온 상황이면 `rules/` 분리 쪽이 이중으로 이득이다.

## 2. 절차

1. 대상(들)을 읽고 현재 줄 수를 보고한다.
2. "절대 하지 말 것", "완료 조건", 트리거 규칙처럼 **매번 지켜야 하는 규칙**만 남긴다.
3. `.claude/rules/`로 분리하는 경우: 내용을 주제별로 나눠 각각 `rules/<주제>.md`에 담고,
   원래 파일에서 그 내용을 들어낸다. `docs/`로 옮기는 경우: 배경 설명("왜 이렇게
   정했는지")을 `docs/` 아래 적절한 파일로 옮기고, 대상 파일엔 경로만 링크로 남긴다.
   옮길 파일이 마땅치 않으면 새로 만들지 말고 사람에게 먼저 물어본다.
4. 옮기기 전/후 줄 수를 비교해서 보고한다.
5. **실제로 파일을 고치기 전에, 사람에게 계획(무엇을 남기고 무엇을 어디로 옮기는지)을
   먼저 보여주고 승인받는다.** 승인 없이 바로 쓰지 않는다.
6. 커밋 자동화 규칙 등 마커(`<!-- xxx:begin -->`/`:end`)가 포함된 블록은 통째로 옮기고
   마커를 그대로 유지한다 — 마커를 지우면 그 규칙을 설치한 스킬이 "설치 안 됨"으로
   오판해 중복 설치하게 된다.

| 남기는 것 | 옮기는 것 |
|---|---|
| 절대 하지 말 것(자주 걸리는 것) | 배경 설명, 왜 그런지 |
| 완료 조건 | 특정 기능에만 해당하는 규칙(→ `rules/<주제>.md`) |
| 파일 위치 지도(참조 링크) | 예시, 상세 절차(→ `docs/`) |

## 3. 관련 스킬

- 이 정리가 필요한 시점을 자동으로 알려면 `watch-rules` 스킬로 세션 시작 훅을 설치한다.
- 정리 후 변경을 커밋하려면 `commit-and-push` 스킬을 쓴다.
