# 분야별 README 규칙과 뼈대

저장소에서 확인한 조건으로 분야를 고른다. 맞는 규칙이 있으면 레퍼런스를 다시 검색하지 않는다.
여러 분야에 걸치면 독자가 처음 할 일을 중심으로 조합한다.
맞는 규칙이 없거나 사용자가 레퍼런스를 지정한 경우는 [새 분야 규칙 만들기](style.md#새-분야-규칙-만들기)를 따른다.

아래 근거는 이미 확인한 사례다. 줄 수와 코드 블록 수는 당시 관찰이며 작성 목표가 아니다.
`<...>`는 저장소에서 확인한 내용으로 채운다. 해당 없는 선택 항목은 지운다.
본문·제목 언어는 기존 README를 따른다. 문서 링크는 목적지에 내용이 있는지 확인한다.
[문서 분리·문장·이미지 기준](style.md)을 적용한다. 검사 대상 제목·표·행은 보존한다.

## E. 연구·에이전트 저장소

- **해당 조건**: 논문·평가 결과 폴더, 벤치마크 실행 코드, 논문 링크·인용 파일 등으로 연구·평가 목적을 확인할 수 있다.
- **README에 남길 것**: 연구 문제·접근·제공 자료 소개 2~3문장, 확인한 결과 한 줄과 범위, 시작·문서 링크, 인용·라이선스.
- **연결된 문서로 넘길 것**: 전체 결과 표, 평가 조건·한계, 재현 절차, 설정·아키텍처 상세. 목적지가 없으면 보존하고 분리를 제안한다.
- **첫 화면**: 연구 내용을 보여 주는 대표 그림·배너와 확인한 논문·문서·CI 배지를 필요한 만큼 쓴다.
- **시작하기 형태**: 문서 링크를 기본으로 한다. 바로 실행할 수 있으면 최소 예시 하나를 둔다. 전체 재현 명령은 연결된 문서로 넘긴다.

**근거 레퍼런스**: [SWE-agent](https://github.com/SWE-agent/SWE-agent/blob/main/README.md)의 배너·배지·문서 진입·인용과 [OpenHands SDK](https://github.com/OpenHands/software-agent-sdk/blob/main/README.md)의 최소 예시·문서·Examples 연결. 두 README에 전체 결과 표·한계·재현 절차가 없는 구성을 바탕으로 결과는 한 줄과 범위만 남긴다.

## B. 라이브러리·프레임워크: 문서 사이트 있음

- **해당 조건**: 패키지 설정·공개 API로 라이브러리나 프레임워크임을 확인하고, 사용 가능한 시작·API 문서 사이트가 있다.
- **README에 남길 것**: 짧은 소개, 시작·API 문서 링크, 필요할 때 설치 한 줄과 최소 예시 하나, 기여·라이선스 안내.
- **연결된 문서로 넘길 것**: 전체 API, 설정 옵션, 튜토리얼, 통합·개발 설명.
- **첫 화면**: 소개와 시작 링크가 보이게 한다. 로고·배지는 사용 판단에 도움이 될 때만 쓴다. UI 스크린샷을 일괄 요구하지 않는다.
- **시작하기 형태**: 문서에서 시작하는 흐름이면 링크만 둔다(Vite). 설치 후 바로 호출하는 흐름이면 설치 한 줄과 최소 예시 하나를 둔다(Express).

**근거 레퍼런스**: [Vite](https://github.com/vitejs/vite/blob/main/README.md)는 확인 당시 66줄·코드 블록 0개로 문서 링크 중심이다. [Express](https://github.com/expressjs/express/blob/master/Readme.md)는 설치 한 줄과 약 11줄의 Hello World를 두고 나머지는 사이트로 연결한다. 예외로 [FastAPI](https://github.com/fastapi/fastapi/blob/master/README.md)는 문서 사이트가 있어도 README에 긴 예제를 둔다.

## F. 라이브러리: 레포 안 문서

- **해당 조건**: 패키지 설정·공개 API로 라이브러리임을 확인한다. 문서 사이트는 없고 `documentation/*.md` 등 레포 안 상세 문서가 있다.
- **README에 남길 것**: 짧은 소개, 설치·최소 사용 예시, 레포 안 상세 문서로 가는 상대 링크, 라이선스.
- **연결된 문서로 넘길 것**: 옵션·API·고급 사용법·오류 처리 등 참조성 설명.
- **첫 화면**: 용도와 최소 사용 흐름을 보여 준다. 배지는 확인한 상태가 필요할 때만 쓴다.
- **시작하기 형태**: 설치와 최소 예시 하나. 전체 옵션을 예시 안에 나열하지 않는다.

**근거 레퍼런스**: [got](https://github.com/sindresorhus/got/blob/main/readme.md)은 README를 짧게 두고 상세를 [`documentation/*.md`](https://github.com/sindresorhus/got/tree/main/documentation)로 연결한다.

## G. 웹 앱·서비스: 문서 사이트 있음

- **해당 조건**: 웹 UI·서버 코드나 서비스 주소가 있고, 사용·설치·운영 상세를 담은 문서 사이트가 있다.
- **README에 남길 것**: 앱·서비스 소개, 이용 주소·시작 링크, 대표 화면, 필요할 때 짧은 아키텍처 개요, 라이선스.
- **연결된 문서로 넘길 것**: 전체 설치·배포, 환경변수·운영, 구성 요소별 아키텍처와 통합 상세.
- **첫 화면**: UI를 이해하는 대표 스크린샷 한 장을 우선한다. 구조가 핵심이면 짧은 구성 개요나 대표 그림을 고른다.
- **시작하기 형태**: 서비스 이용·문서 링크를 기본으로 한다. 패키지로 제공되면 설치 명령 한 줄만 덧붙일 수 있다.

**근거 레퍼런스**: [Excalidraw](https://github.com/excalidraw/excalidraw/blob/master/README.md)는 설치 명령과 스크린샷 한 장을 두고 상세를 docs 사이트로 넘긴다. [Supabase](https://github.com/supabase/supabase/blob/master/README.md)는 아키텍처 개요만 README에 두고 상세는 docs로 연결한다.

## H. 자체 호스팅 웹앱: 문서 사이트 없음

- **해당 조건**: 자체 호스팅 실행·배포 설정이 있고 문서 사이트가 없다. 별도 설치·배포 문서가 없거나 README만으로 설치·배포해야 한다.
- **README에 남길 것**: 요구사항, 설치, 필수 환경변수, DB 준비·마이그레이션, 빌드·실행·배포·접속 확인 절차.
- **연결된 문서로 넘길 것**: 긴 전체 환경변수 참조표, 통합·운영 설명은 별도 문서 분리를 제안한다. 이동할 수 없으면 README에 보존한다.
- **첫 화면**: 앱 소개와 필요할 때 대표 화면을 둔다. 설치·배포 절차를 찾기 쉽게 한다.
- **시작하기 형태**: 전체 설치·배포 절차. 실제 명령 의존 순서를 따르고 필수 설정·외부 서비스를 생략하지 않는다.

## C. 내부 패키지·모노레포 하위

- **해당 조건**: 루트와 분리된 패키지 디렉터리·설정이 있고, 루트 문서·라이선스나 내부 팀의 소유자·사용 범위를 확인할 수 있다.
- **README에 남길 것**: 용도, 확인한 상태·연락처, 실행 위치, 최소 사용법, 관련 문서·루트 링크, 적용 라이선스.
- **연결된 문서로 넘길 것**: 공통 설치·개발 규칙은 루트 문서로, 상세 사용법은 패키지 문서로 연결한다.
- **첫 화면**: 패키지의 역할과 내부 전용·사용 범위가 먼저 보이게 한다. 로고·스크린샷은 기본으로 요구하지 않는다.
- **시작하기 형태**: 확인한 실행 위치와 최소 예시 하나. 루트 설치로 충분하면 별도 공개 설치 절차를 만들지 않는다.

**근거 레퍼런스**: [Google README 가이드](https://google.github.io/styleguide/docguide/READMEs.html)의 용도·상태·연락처·사용법·문서 링크 구성을 따른다.

## A. CLI·소규모 라이브러리

- **해당 조건**: CLI 진입점이나 작은 공개 API가 있고, 설치 후 최소 호출로 시작할 수 있다. 엄격 준수는 사용자가 standard-readme 명세 준수를 요청했을 때 적용한다.
- **README에 남길 것**: 소개, 요구사항·설치, 최소 사용 예시·확인한 출력, 필요한 개발·기여 안내, 마지막 라이선스.
- **연결된 문서로 넘길 것**: 긴 옵션·API·개발 상세는 실제 문서가 있으면 연결한다. 없으면 필수 정보는 README에 남긴다.
- **첫 화면**: 무엇을 하는지와 복사 가능한 시작 명령을 보여 준다. CLI는 이미지보다 코드·출력 텍스트를 우선한다.
- **시작하기 형태**: 설치와 최소 예시 하나. 명세 준수 요청이 없으면 간단형으로 쓰며 엄격 준수라고 부르지 않는다.

**근거 레퍼런스**: [standard-readme](https://github.com/RichardLitt/standard-readme/blob/main/spec.md)의 설치·사용·기여·마지막 라이선스 흐름. 엄격 준수 요청에는 아래 별도 조건을 함께 적용한다.

## standard-readme 엄격 준수

사용자가 명세 준수를 요청할 때만 적용한다. 일반 입구형을 완전 준수라고 부르지 않는다.

- 순서: Title → Banner → Badges → Short Description → Long Description → Table of Contents →
  Security → Background → Install → Usage → (추가 섹션) → API → Maintainers → Thanks → Contributing → License
- 한 줄 설명은 별도 제목 없이 120자 미만으로 쓴다. 제목과 패키지 설명의 일치를 확인한다.
- 필수 Install·Usage에는 코드 블록을 둔다. 선택 섹션은 분량을 채우려고 넣지 않는다.
- Contributing은 필수다. 문의 경로·PR 수락 여부·기여 조건을 요약하고 상세 문서가 있으면 링크한다.
- License는 확인한 SPDX 정식 이름 또는 식별자와 저작권자를 적어 마지막에 둔다.
- 목차는 100줄 이상이면 필수이고, 100줄 미만이면 선택이다. 일반 README는 탐색 필요성과 GitHub Outline으로 판단한다.

그 밖의 조건은 [standard-readme 명세](https://github.com/RichardLitt/standard-readme/blob/main/spec.md)를 확인한다.
